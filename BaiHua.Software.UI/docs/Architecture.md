# BaiHua.Software 上位机通用框架 - 架构设计文档

## 📋 项目概述

BaiHua.Software 是一个**上位机（SCADA/HMI）通用框架**，基于 .NET 8 构建，采用**分层架构 + 模块化设计**，为工业自动化应用提供完整的业务支撑。

**技术栈**：
- **开发框架**：.NET 8
- **UI 架构**：WPF + **Prism 9.0** (模块化 MVVM + EventAggregator 事件总线)
- **依赖注入**：Prism.DryIoc 
- **主机框架**：Microsoft.Extensions.Hosting
- **ORM 与数据持久化**：FreeSql (多库方言支持 + Fluent API 防腐映射)
- **日志架构**：Serilog
- **工控通信与硬件**：HslCommunication (PLC), OpenCvSharp4 (机器视觉) 等底件 (封装于 HAL 层)

---

## 📦 核心模块详解

### 1️⃣ **Common (01 BaiHua.Software.Common)** - 公共工具层

**职责**：提供全局通用的底层帮助类、基础工具函数和通用扩展方法。

**设计原则**：
- 🛠️ **DRY (Don't Repeat Yourself)**：提取通用逻辑，避免代码重复。
- 🛠️ **强封装性**：隐藏复杂底层实现，对外提供极简 API。
- 🛠️ **无状态**：尽可能设计为纯函数或静态方法，不持有任何业务状态。

**主要依赖**：
- 基于原生 BCL (Base Class Library) 及辅助型第三方库（如 `Newtonsoft.Json`）。
- **零业务依赖**。

**主要功能**：
- 📦 **数据转换与序列化**：JSON/XML 等常规数据结构序列化封装，以及工控通信极强相关的**字节流封包解包**与**字节序转换（Endianness）**工具。
- 🔐 **安全性与密码学**：常用的加解密算法库（AES/RSA/MD5/SHA 等），以及可能涉及设备授权的系统软硬件机器码指纹截取基础支持。
- 📁 **IO 与配置抽象**：INI/JSON 等格式配置文件的读写解析，以及带有共享安全防冲突机制的健壮本地目录与文件访问管控。
- 🛠️ **核心语法扩展包**：针对基础类型（String 解析、IEnumerable 集合操作、Enum 反射缓存、DateTime 高精转换等）的高频使用 C# 扩展方法（Extensions）。
- ⚙️ **基础支撑与容错**：全局唯一 ID 生成（如雪花算法）、网络或底层通信的通用重试/补偿机制（RetryHelper）、对象深拷贝机制以及性能追踪评估工具（精准 Stopwatch 包装等）。

**特点**：
- ✅ **高度独立**：处于依赖链的最底层，即使脱离本平台也可复用于其它非上位机项目。
- ✅ **安全共享**：可被架构中所有层级直接且安全地引用与调拨。

**项目结构**：
- `/Extensions`：各常用数据类型的扩展封装。
- `/Helpers`：各类针对文件读写、加密等通用帮助类。
- `/Utils`：基础计算或唯一 Id功能组件等。

### 2️⃣ **Core (02 BaiHua.Software.Core)** - 核心契约层

**职责**：定义系统的纯粹基础契约与业务骨架，属于全架构体系中的核心模型规范区。

**设计原则**：
- 🔒 **依赖倒置原则 (DIP)**：只抽象接口及其防腐规范，绝不涉猎具体的技术实现细节。
- 🔒 **面向契约设计**：建立跨业务与全模块互认的标准实体模型集合。
- 🔒 **实体纯粹性（POCO）**：领域实体与数据模型（如 `Report`, `AxisParam`, `CameraConfig`）**绝对不应继承 `INotifyPropertyChanged` 等 UI 强相关接口**。它们仅用作纯粹的数据荷载，若需实现 UI 界面双向数据绑定，必须在表现层（Modules/UI 层的 ViewModel）建立新实体并进行二次映射。

**主要依赖**：
- 仅依赖 `Common` 层提供基础数据结构支撑（可选）。此层拒绝直接依赖任何具体的横向或上层模块。

**主要功能**：
- **Interfaces**：定义多方参与的通讯协议和规范边界（如 `IDashboardAppService`, `ICamera` 等抽象能力封装定义），作为上下层的规约纽带。
- **Enums**：全局状态枚举的中心枢纽（如工作站运行模式 `WorkstationStatus`）。
- **DTO / Domain Models**：数据传输对象标准以及实体映射模板，例如系统业务流转与存盘数据 `Report`、视觉相机配置结构 `CameraConfig`、控制轴运动参数 `AxisParam`，以及 `DashboardData.cs`, `SettingsData.cs` 等。所有的实体或 DTO 均维持绝对纯净。

**特点**：
- ✅ **最底层的契约堡垒**：所有外部层必须遵循这里的规范，其编译产物最纯净。
- ✅ **高稳定性**：接口一经确立修改阻力极大，变动需极其慎重以保证上下线耦合系统的稳定兼容。

**项目结构**：
- `/Domain` / `/DTO`：存放业务实体核心模型包（如 `Report` 数据实体验证实装载体结构）。
- `/Application`：定位于应用服务接口抽象及通用数据报文。
- `/Hardware`：定位于工业层各类自动化执行运动机构与感知反馈卡的纯接口存留地，以及配套纯数据参数包存放处（如存入定义好的 `AxisParam`, `CameraConfig` 配置实体系）。

### 3️⃣ **Infrastructure (03 BaiHua.Software.Infrastructure)** - 基础设施层

**职责**：处理系统的非业务重载底层实现技术细节，主导包含数据库持久化交互（基于 FreeSql）、本地强日志落地系统（基于 Serilog）的构建与对接。

**设计原则**：
- 🏗️ **底层设施隐藏**：全盘接管并实现 `Core` 层中剥离出的仓储契约（Repository）和各类依赖外部存储环境的服务互通。
- 🏗️ **防腐拦截与映射**：严格控制 ORM 框架特性向内的渗透。须通过 Fluent API 方式外置配置表结构，坚决维护领域模型（Core 层 POCO 实体）的纯洁性。
- 🏗️ **隔离副作用**：一切引起外部非机电环境发生永久改变（如写盘、库表建构更改、第三方 MES 接口网络打流请求等）的操作，统筹归拢在本层处理。

**主要依赖**：
- 引入轻量强大的数据库引擎体系（`FreeSql` 及其各强类型提供者 Provider如 `FreeSql.Provider.Sqlite` 等）与 `FreeSql.Repository` 扩展。
- 工业工程级文本监控体系（`Serilog` 及其 File / Console Sink 扩展向组件）。
- 向上依赖 `Core` 的核心实体规范层予以驱动和映射。

**主要功能**：
- 🗄️ **ORM 引擎联结与上下文管理**：基于 `FreeSql` 提供具体的单例多段数据库联通管控（`IFreeSql` 注入定义）、实体多级缓存及 CodeFirst 结构强链同步支持。
- 📊 **实体数据仓储与工作单元**：利用 `FreeSql` 实现泛型仓储模式及 UnitOfWork工作单元，拦截与支撑跨表跨库事务控制、安全游标查询与提交。
- 📝 **日志系统联动与策略驱动**：除了常规规制（按天数或大小对业务数据进行切片留档）外，与 FreeSql 结合完成慢 SQL 查询埋点与运行栈深度监视追踪记录等融合服务。

**特点**：
- ✅ **多形态无感切换**：依赖 `FreeSql` 强大的多库方言支持特性，可以在实施部署时动态或平滑切换真实承载库（比如单机态跑 SQLite 切入厂区大线跑 MySQL 等），上层零感知。
- ✅ **统一门面隔离复杂**：将连接池状态调度、数据库读写锁逻辑、缓存同步策略与特定 SQL 汇编器管理的复杂性完全封闭内部。

**⚠️ 采用 FreeSql 对【Core (02) - 核心层】的影响与架构规约评估：**
若基于 FreeSql 实现落盘持久化，**绝不可以污染 Core层架构**。遵循应对要求如下：
1. **零侵入底层保护（拒接 FreeSql.DataAnnotations）**：为了保持 `Core` 层的终极“实体纯粹性（POCO）”，**严禁**在 `Core` 层项目及包括 `Report` 等实体上面引入任何 `FreeSql` 相关 DLL 或依赖，绝不可使用诸如 `[Column(IsPrimary = true)]` 等特定框架特性。
2. **⭐️ 映射方案剥离（Fluent API）- 【首选方案】**：一切表名指定、映射关联、主键规范、自增控制等 ORM 参数动作，必须**交由 Infrastructure 层**利用 FreeSql 的 **Fluent API（如 `CodeFirst.ConfigEntity<T>`）** 集中进行外置绑定完成实体表配置映射初始化。这是最符合架构防腐原则的官方推荐做法。
3. **退让底线**：即使必须依赖特性标签来加速标定字段，实体内也**仅限使用 C# 内置的 `System.ComponentModel.DataAnnotations` 指示**（如 `[Key]`, `[StringLength]`，这些是 FreeSql 自然内置支持项，同时它属于 C# BCL，不算弄乱 Core 层的干净依赖链）。

**项目结构**：
- `/Data` 或 `/Repositories`：基于各类底层对象包装的仓储支持以及 `DbContext`/`IFreeSql` 的实现。
- `/Logs` / `/Logging`：集成 Serilog 全局钩子钩落和管道构建包。

### 4️⃣ **HAL (02 BaiHua.Software.HAL)** - 硬件抽象层

**职责**：直接面向生产装备，封装具体厂商型号（包括运控、视觉、IO卡、PLC等）的底层驱动为可编程的标准接口规范。

**设计原则**：
- 🔌 **适配器与专属工厂配置模式**：将繁杂的专有厂方函数包封装成系统规范的入口形式。**必须针对每一类硬件组件建立专属工厂（如 `MotionFactory`, `CameraFactory`, `IOCardFactory`）**，通过统一调度配置，在系统拉起时动态反射或显式创建并分发对应的驱动实例实体。
- 🔌 **高内聚解耦与热插拔**：在实现上保持硬件模块组件独立不干涉。板卡或驱动出现变更，只需替下原有驱动 DLL 或新建对应的实现类（如将 `AdlinkMotion` 驱动替换为 `GtsMotion`），不对上层造成任何污染。
- 🔌 **接口与数据防腐规约（严格遵守）**：
  1. **接口上抛**：**HAL 层只负责写实现，一切硬件抽象接口（如 `ICamera`, `IMotion` 等）必须且只能定义在 `Core` 层**，从而保证上层调用时不依赖任何具体 HAL DLL。
  2. **数据结构中立映射转换**：坚决禁止 `Core` 层的接口签名暴露厂方专有对象（如海康 SDK 的 `MV_FRAME_OUT`，或 Halcon 的 `HObject`）。`Core` 层必须仅使用基础类型或定义**厂商无关的中立数据结构**（如通用的 `ImageBuffer`、`AxisPoint`）。**HAL 层的实现类必须默默承担厂方特定 SDK 对象与 Core 中立对象互相转换/映射的责任**，以此彻底切断硬件污染源。

**主要依赖**：
- 调用各大底层厂方（如研华、固高、汇川、海康、基恩士等）级别的专属 SDK 包或驱动 API。
- 机器视觉底层常常依赖 `OpenCvSharp4` 等组件，而在车间网络与设备协议互通方面，**针对 PLC 交互，强烈推荐采用 `HslCommunication`** 库来达成主流工业 PLC 的一站式极速适配。

**主要功能**：
- 🏃 **运动控制支持（Motion）**：必须依附于 Core 层的自定义接口 `IMotion`，多态实现各品牌 PCI/PCIE 卡/EtherCAT 控制器的接驳、归零与 PTP 命令包装。**由 `MotionFactory` 依据设备参数组装实例化。**
- 📷 **机器视觉引擎（Camera）**：必须依附于 Core 层的自定义接口 `ICamera`，实现各类二/三维相机参数下发、触发采集以及图像帧提取到特定缓存中立对象的动作。**由 `CameraFactory` 负责扫描挂载。**
- 🎛️ **基础电气控制（IOCard）**：必须依附于 Core 层的自定义接口 `IIOCard`，完成厂牌数字量输入输出卡干接点高低电平翻转读取及中断捕获。**依托 `IOCardFactory` 实例调拨。**
- 📡 **车间网交互（PLC）**：利用 `HslCommunication` 打底，支持大吞吐量的寄存器区实时读写通信拦截整合。**通过 `PLCFactory` 提供链路。**
- 💻 **软状态推演模拟器（Simulation / Mock）**：为切断对物理环境的硬依赖，**针对 `Motion`, `Camera`, `IOCard` 三大强排他组件，必须强制配套建立一套脱机的 Simulation 虚拟驱动**（如 `MockMotion`, `MockCamera`, `MockIOCard`），以便开发人员在无设备环境下随时离线完成跑单联调。这些 Mock 类同样纳入各自归属领域的 Factory 实例化清单中支持切换派发。

**特点**：
- ✅ **防腐屏障 (ACL)**：它是保卫整个软件业务层逻辑基石的绝对前线，完美防御各类硬件 SDK 版本大变迁带来的代码污染危机。降解了不同产商带来的实现门槛，保证调用语系的单纯一致。

**项目结构**：
- `/Motion`：控制端板卡控制体系与专属厂构建器（含 `MotionFactory.cs`, `GugaoMotionCard.cs`, 等）。
- `/Camera`：相机采集硬件绑定体系与专属构建器（含 `CameraFactory.cs`, `HikCamera.cs`, 等）。
- `/IOCard`：触发/限位反馈采集层控制板卡通讯体系（含 `IOCardFactory.cs`）。
- `/PLC`：通信栈下沉实体配置层与协议生产器（含 `PLCFactory.cs`）。
- `/Simulation`：全套设备的 Mock 实现存放池（如 `MockMotion.cs`, `MockCamera.cs`）。
- 包含顶层统一路由调度统筹口如 `HALContext.cs`，其将下属各大 Factory 提供的大类设备实例集结注入系统 IoC 容器。

### 5️⃣ **Services (04 BaiHua.Software.Services)** - 应用服务层

**职责**：提供围绕系统的核心软件业务管理领域服务，承载不随单一机台变数动荡的基础支撑。全面包含用户、硬件资产配置、配方、系统配置、报警聚合以及审计追溯等全系统级的纯业务逻辑功能。

**设计原则**：
- ⚙️ **单一职责 (SRP) 与领域边界**：每个核心域仅处理所属业务，如权限服务与硬件逻辑服务必须划清横向边界，解耦且互不干涉。
- ⚙️ **无状态与依赖注入**：服务层应尽量设计为无状态（针对单次请求计算）或受管单例，坚决抵制直接使用静态类和硬编码调度，所有业务类的协同必须依靠接口通过 IoC (DryIOC) 依赖注入。
- ⚙️ **纯后台防腐化**：作为后台领域服务，**绝对禁止引入任何 WPF (UI) 相关的依赖**（如 `MessageBox`）或前台弹窗逻辑。

**主要依赖**：
- 依赖向下打通 `Infrastructure` 落实数据库查询和运行日志持久化处理；横向引用 `Common` 获取通用工具；纵向紧密依赖底层 `Core` 的契约模型（通过实体 Domain 或 DTO 交互传递）。

**主要功能（包含但不限于）**：
- 👤 **用户与权限管理 (User Management)**：基于 RBAC（角色权限控制），负责身份核验、登入登出拦截、密码哈希加盐换算、时效 Token 管理，并提供权限验证断言逻辑。
- 📟 **设备资产与参数管理 (Hardware Management)**：*(注：与负责通讯和执行驱动的 HAL 层不同)* 负责高维度的**纯业务级别逻辑管理**。例如：多设备基础配置信息存档管理、更换周期与寿命追踪、通信参数表存储加载等。
- 📜 **配方与工单管理 (Recipe Management)**：产线核心工艺生产参数的数据生命周期及下发管控。具备复杂数据参数的多模态增删改查 (CRUD)、版本历史留存追踪，以及与 JSON/XML 接口的文件互导互通。
- ⚙️ **配置服务管理 (Configuration Management)**：统筹整套系统通用环境级设定文件的逻辑存取，涵盖：开发联调开启项、环境路径映射配置、定期运维清库周期的全局维护与加载。
- 🚨 **系统报警与事件管理 (Alarm Management)**：采集汇总上游与底层的一切严重异常中断与提示事记。维持当前正处于激活的报警列表池 (Active Alarms)，实现手动防呆复位拦截机制，并将所有报警历史无损归档写入。
- 🛡️ **审计与追溯记录 (Audit Trail)**：面向合规性（参照医疗级 FDA 21 CFR Part 11 要求）建设的操作纪实防伪拦截墙。无疏漏拦截全部状态变更动作，留下关键存根数据：“操作人、确切时间、被调整功能、旧值与新值详情对比”。

**特点**：
- ✅ **高度复用软资源库**：彻底剥离具体光机电硬件执行层面的污染噪音，纯粹由代码交互构建出稳定严密的业务机制墙。整层可几乎不修改地直接复用于不同现场的项目中。
- ✅ **纯净零外部干扰测度**：因设计为纯服务，极为适合结合 XUnit 类测试框架注入 Mock 数据伪造 Infrastructure 进行 100% 容量的自动化快速联调单元测试。

**项目结构**：
- `/User`：用户验证策略解析、账户角色验证服务领域抽象。
- `/Hardware`：管控设资产台账档案、标定及生命周期逻辑服务。
- `/Recipe`：工作参数表控制中心管理服务、版本校验。
- `/Config`：常规系统环境属性存取策略封装。
- `/Alarm`：系统报警机汇流缓存及消息派发中心。
- `/Audit`：审计截断分析与操作对比追溯日志落地推演等服务。

### 6️⃣ **BLL (05 BaiHua.Software.BLL)** - 业务逻辑层

**职责**：系统全景工艺流程与工位动作的核心调度方，负责深度协调指挥底层硬件执行机构和中间支撑服务，实现非标自动化专机的具体加工流转逻辑。

**设计原则**：
- 🧠 **严格依赖倒置 (DIP) 与接口调用**：**BLL 层绝对禁止直接引用或实例化 `HAL` 层的具体对象**。BLL 必须且只能调用 `Core` 层中定义的硬件抽象接口（如 `IMotion`、`ICamera`），运行时依托宿主的 IoC 容器完成真实 HAL 驱动实例的注入解耦。
- 🧠 **模型/状态机控制**：使用成熟的状态机引擎或任务流线管控工位的流程跳变，将复杂的设备流转与首件归零逻辑标准化，消灭极度分散、难以追踪的高危 `if-else` 面条代码。
- 🧠 **外观模式 (Facade)**：对上层表现层（暴露简明的干练动作和状态事件接口（如“系统启动”、“整机急停”），内部隐藏包装底层几十数百个繁杂的分散控制信号与动作序列。

**主要依赖**：
- **下层依赖**：横向依赖 `Services` 层获取配方/权限/系统配置/审计落盘能力；**核心纵向依赖 `Core` 的模型与防腐接口体系**（基于契约通信）。
- **坚决不直接依赖 `HAL`**，不产生横向程序集硬耦合。

**主要功能**：
- 🔄 **工站管控与流程流转 (Workstation Engine)**：针对不同自动化干涉工站（如：上下料站、传送带、视觉对位检测站、贴合站）管理单站并行或串行的流水流转任务生命周期（如 `DashboardAppService.cs`, `WorkstationAppService.cs`）。
- 📝 **轨迹与执行逻辑映射**：拿到 `Services` 层抛出的验证配方，执行工艺算法分析，拆解转化为具体的伺服电机点位运转轨迹集或气缸触发时序序列，通过推给 Core 层接口让底层干活。
- 🛡️ **生产容错与卡死干预**：捕捉处理全生产运行期的软硬件异常状态、安全光幕干涉降级预警、系统急停紧急锁定保护，并提供异常排查后的继续运转断点恢复策略。

**特点**：
- ✅ **非标定制浓度最高**：作为设备的“中枢大脑”，此层直接反馈了专机专案的独有非标工艺流程。通常，更换不同机台的软件，此层代码替换及重构率最高。
- ✅ **时间片高协同性考验**：多轴插补联动、视觉飞拍握手、设备 IO 气缸安全防撞交互的并行集散地，代码时间要求严苛。

**项目结构**：
- `/Application`：对外暴露出可由 UI 层 ViewModel 触发的应用服务控制方法与只读属性绑定契约。
- `/Workstations` / `/Flows`：细分具体流转工站（如：LoadStation、DispenseStation）的基础有限状态机（FSM）或流转步进（Step）实体控制类。

### 7️⃣ **Modules (06 BaiHua.Software.Modules)** - 业务组件模块层

**职责**：作为平台前端展现的主力军，基于 UI 解耦生态的分治原则，承载各个特定领域业务（如运行监控、硬件单动、配方编辑）的 XAML 视图 (Views) 和对应的视图模型 (ViewModels) 封装。

**设计原则**：
- 📦 **模块化绝对隔离**：各业务组件模块（如 `Dashboard` 与 `Settings`）属于平级的独立沙盒，**严禁各个模块层级间的相互越权引用或硬编码强耦合**。
- 📦 **事件总线与路由导航通信**：跨视图或跨业务模块间的参数抛递与协同呼叫，必须强制应用低耦合介质，如 `Prism` 的 `EventAggregator` (发布/订阅机制) 或基于 `Region` 区域的导航传参（Navigation）。
- 🎨 **MVVM 数据呈现防腐映射**：坚守贯彻 `Core` 层领域实体的纯粹性。本层的 `ViewModel` 必须包揽并吸收一切与界面双向特性相关的污染代码（如继承 `INotifyPropertyChanged`）。将底层传递过来的纯净 `DTO` 或 `Domain Model` 实体，在本层手动映射或包装为专门服务于 WPF UI 控件的展示类数据结构。

**主要依赖**：
- 前端强依赖 `Prism.Wpf` 等展示套件支撑模块化运行环境；向下对接请求 `BLL` 和 `Services` 提供应用数据与操作响应；向底层依赖 `Core` 层的接口与模型进行业务交互。
- 🚫 **绝对红线**：**严禁任何 UI 或模块层（Modules）代码直接引用、操作或实例化 `HAL` 层的具体硬件实现！**哪怕是 `Hardware`（硬件调试面板）这样的强相关视图，也必须只通过 `Core` 层的规范接口（如 `IMotion`, `ICamera`）进行单动测试调用，运行时利用 IoC 容器拿取驱动对象。

**主要功能（包含核心业务 UI 块）**：
- 🖼️ **具体领域视图与逻辑承载**：完全接管各大业务服务层的前端视图映射及数据交互逻辑。核心承载模块包括：
  - **主控运行展现 (Dashboard)**：集中展示机台运行状态、OEE、实时产能数据、整体流转动画及运行日志流的综合首屏。
  - **硬件单动调试 (Hardware)**：各工站轴组伺服点动/归零、气缸/IO 手动强制置位与监视、视觉相机实时画面预览及标定的纯调机控制前台。
  - **配方与工单交互 (Recipe)**：二维或树形工艺参数表格页面，支持向后端发起“配方切换/另存/下发设备”的业务指令映射。
  - **参数设置 (Settings)**：包括全局环境配置、通信网段IP绑定等系统级运行门槛环境参数配置窗。
  - **账户与权限面 (User)**：处理登录验证弹窗、基于 RBAC 的角色树状授权勾选及账户启停操作面板。
  - **报警与日志面 (Alarm/Audit)**：查询历史或当前活跃的报警清单数据网格、处理报警确认/复位、以及操作行为审计表格条件的联合筛选呈现。
- 🪝 **模块自组装与路由注册 (`IModule`)**：各子业务依据实现 Prism 提供的 `IModule` 接口契约，在自身的生命周期钩子中，自行向主容器内聚注册独有的导航视图（Navigation）、弹窗服务（Dialog）及域内私有实例。
- 🕹️ **前端防呆与指令传导 (Commands)**：汇聚收集使用者的行为特征并转化为 `RelayCommand/DelegateCommand` 指令。提供前端基础的必填/越限格式合法性校验，并利用工位实时反馈状态动态拦截非法操作按钮（通过指令的 `CanExecute` 实施 UI 停亮防呆控制）。

**特点**：
- ✅ **平滑的无限增量扩展系统机制**：若新添菜单功能域，仅需新建一个模块文件夹或类库，完成契约注册放入工程即可。真正落实“增加功能只需添加代码而非修改代码 (开闭原则 OCP)”，隔绝主线工程关联坍塌风险。
- ✅ **卓越的分工协同效率**：边界清晰，保护屏障免遭前端滥用。不仅保证了工程干净利落，更让不同 UI 开发人员在实现自身所属界面特征时实现完全无冲突并行研发并行对接。

**项目结构（Prism 独立子模块群）**：
- `/GlobalUsings.cs`：声明规约本层通用 UI 及常驻依赖的命名空间。
- `/Base`：提炼供各兄弟隔离模块分享互用的纯前端 UI 底件资源（如 通用的 Converter、校验 Rule、扩展 Behavior 以及基础 UI 顶层控件）。
- `/Dashboard`：主控台调度画面、系统实时工艺流水渲染面板模块。
- `/Hardware`：分立式单设备（轴、卡、相机、PLC）机电结构剥离诊断交互面板。
- `/Recipe`：核心业务配方表的拉取、编辑确认和追溯管理的前端视图包。
- `/Settings`：整机开发级/用户级配置管理视图包。
- `/User`：人员登录、鉴权与角色维护面板。
- `/Workstation`：具体工艺工站的监视器视图包。
- `/Alarm` (可选/合并)：当前活跃告警栏与历史警告数据追溯。

### 8️⃣ **UI (100 BaiHua.Software.UI)** - 用户界面层 (Shell 端)

**职责**：作为整个上位机软件的**宿主外壳 (Shell) 与生命周期管理起点**，负责搭建主界面的全局母片骨架、管理各视图插槽 (Region)，并担任系统所有底层服务和硬件驱动的“最终聚合装配车间”。

**设计原则**：
- 🎨 **空壳架构 (Thin Shell)**：UI 宿主工程内绝不编写具体的重度分析代码与业务功能画面。所有真正的界面交互均应下放到 `Modules` 层的子模块中，宿主仅充当它们的调度器和显示容器。
- 🎨 **集中装配与 IoC 根 (Composition Root)**：作为系统的入口，在此处彻底实现所谓的“控制反转”。接管 Prism 的 `DryIOC` 容器初始化过程，将 `Infrastructure`仓储、`Services`功能、`BLL` 业务中心以及最底层 `HAL` 层的各类硬件驱动工厂进行反射整合，完整对接绑定到 `Core` 的各项接口上。

**主要依赖**：
- **终极聚合点**：引用贯穿架构级的几乎所有底层项目：通过引用 `Modules` 将独立业务囊括；通过引用 `Infrastructure` 和 `HAL` 连通运行时的真实操作实体与数据库引擎。
- 强依赖 `Prism.DryIoc` 构建模块化体系，依赖 `Microsoft.Extensions.Hosting` 把控宿主生存期。

**主要功能**：
- 🗂️ **全局模块扫描与注册 (Module Catalog)**：通过重写 Prism 的 `ConfigureModuleCatalog` 构建器流，静态或动态发现并加载位于 `Modules` 层的各个兄弟沙盒组件（例如 `DashboardModule`, `SettingsModule`）。
- 🧭 **主容器布局与路由导航 (Region & Navigation)**：搭建全局性的主界面 `MainWindow.xaml`，规划出菜单区（`MenuRegion`）、主工作区（`MainRegion`）等控件树占位符。实施和统筹跨越不同 Module 项目的基于 URL 形式的路由导航。
- 👮 **生命周期阻断与权限防卫 (Permission Guard)**：拦截启动过程调出用户登录窗体（阻塞直到成功登入）。在用户点击主菜单请求导航或切换核心模块视图前，结合 `Services` 层的权限体系进行动态可见性核验，实现无权限菜单的隐藏或无权限路由的拦截断言。
- 🛡️ **全局异常兜底捕获**：在应用入口（`App.xaml.cs` 中实现 `DispatcherUnhandledException` 或 `UnobservedTaskException` 钩子）接管系统级的致命崩溃错误，保障工业软件面对未知错误时的状态保护及 Serilog 崩溃留档日志的无损上报。

**特点**：
- ✅ **大统筹零生产**：自己不直接生产具体业务视图（除了壳体），但全权负责分配内存容器和制定拼图组装次序。
- ✅ **线程保护神**：掌握着 WPF 最核心的 UI 调度线程 (Dispatcher)，为下位组件在跨线程回调时提供同步上下文支撑。

**项目结构**：
- `App.xaml` / `App.xaml.cs`：主引导程序的启动驻留点（Bootstrapper），包含 IoC 注册、模块挂载、全局日志实例注入及全局异常捕获钩子的集中配置。
- `/Views/MainWindow.xaml`：包含标题栏、状态栏、侧边栏及 Prism Region 主展现占位标识的设计外壳母片。
- `/ViewModels/MainWindowViewModel.cs`：主要提供整机外壳级别的状态映射逻辑（如：右上角的显示登录账户名称、系统托盘系统时钟、顶部导航一级菜单的指令调度命令等）。
- `/docs`：核心架构设计、团队统一开发规约等文档的维护存留工程库。
